## 1. AI Session Rules

When an AI assistant operates on this repository, these rules apply without exception:

### DO:
1. **Read `.pramedha/agent-instructions.md` first** — it defines the master 28-step fill protocol (Steps 0–27).
2. **Consult the Minimum Context Router in `AGENTS.md`** — load only the minimum 2–4 files required for your specific task.
3. **Check `ops/session-handoff.md`** for prior session decisions and ongoing context.
4. **Check `ops/authority-map.md` before editing** — always know which file is authoritative for what data.
5. **Tag every claim with verification status** (✅ VERIFIED / ⚠️ ESTIMATED / ❌ UNVERIFIED).
6. **Cross-reference across sources** — never rely on an unverified single document.
7. **Ask when uncertain** — never fabricate or hallucinate career data.
8. **Update `ops/session-handoff.md`** at the conclusion of every career session with career progress, decisions, and evidence gaps.

### DON'T:
1. **Never fabricate claims, metrics, or credentials** — leave fields blank if evidence does not exist.
2. **Never share `personal/` content** in outward-facing assets (resumes, LinkedIn, cover letters).
3. **Never edit files in `tools/resume/generated/`** — they are auto-generated by `tools/resume/assemble.py`.
4. **Never strip verification tags** (✅/⚠️/❌) — they form the core trust layer of the operating system.
5. **Never use old resume bullets as sources of truth** — `identity/*.yaml` is the sole source.
6. **Never log template/codebase development into `ops/session-handoff.md`** — `session-handoff.md` is strictly for the user's career context, facts, decisions, and application progress. System/codebase changes belong in `.github/CHANGELOG.md`.

## 2. Core Tool Stack & Pipeline Architecture

### System Tools

| Tool | Purpose | Status |
|------|---------|:------:|
| **Text Editor / IDE** | Primary editor for YAML and Markdown files | ✅ Required |
| **Git** | Version control for all career data and claim histories | 🟢 Recommended |
| **Python 3.10+ & PyYAML** | Automated cascade assembly, sync, and validation | ✅ Core Runtime |
| **assemble.py** (`tools/resume/assemble.py`) | Resume cascade engine (master → variants) with `--orphans` check | ✅ Included |
| **sync.py** (`tools/resume/sync.py`) | Two-way identity <-> master.yaml synchronizer | ✅ Included |
| **validate.py** (`.pramedha/validate.py`) | Template integrity, schema enums, and fill rate validator | ✅ Included |
| **RenderCV** | Resume rendering from assembled YAML → ATS-optimized PDF | 🟡 Optional Automation (`pip install rendercv`) |

### Resume Cascade Pipeline

```
identity/*.yaml ──┐
                  ├──> tools/resume/master.yaml ──> assemble.py ──> tools/resume/generated/*.yaml ──> RenderCV ──> PDFs
tools/resume/design.yaml ┘              ▲
tools/resume/variants/*.yaml ───────────┘
```

| Component | Path / Tool | Responsibility |
|-----------|-------------|----------------|
| **Source Career Data** | `identity/*.yaml` | Verified facts (experience, skills, credentials, projects) |
| **Master Bullet Pool** | `tools/resume/master.yaml` | Keyed bullet pool with length & phrasing variants |
| **Design Specifications** | `tools/resume/design.yaml` | Typography, margins, colors, page spacing |
| **Role Overlays** | `tools/resume/variants/*.yaml` | Per-target-role bullet selection and section ordering |
| **Cascade Engine** | `tools/resume/assemble.py` | Assembles final single-document YAML for RenderCV |
| **Synchronizer** | `tools/resume/sync.py` | Imports new bullets & syncs experience, projects, education |
| **PDF Renderer** | RenderCV | Generates pixel-perfect, ATS-compliant PDF resumes |

## 4. Anti-Inflation Rules

> These 6 rules prevent resume drift — the gradual, unconscious inflation of claims over time.

1. **No rounding up experience duration:** "Nearly 3 years" ✅ · "4+ years" ❌.
2. **No future credentials in present tense:** Do not list certifications or degrees until officially completed/passed.
3. **No headcount claim without evidence:** "Led team of 6 engineers" requires proof (org chart, sprint board, peer evidence).
4. **Latest dated evidence wins:** When numbers conflict across sources, use the figure backed by the latest dated primary source.
5. **Estimated ≠ Measured:** Explicitly tag all metrics: `[measured]` or `[estimated]`. Estimated claims receive ⚠️, never ✅.
6. **Zero private leakage:** Information in `personal/` NEVER appears on resumes, cover letters, or public profiles.

## 5. Maintenance Rituals

### Weekly (5 minutes)
- [ ] Log this week's accomplishments in `journal/work-log/`
- [ ] Record wins and milestones in `journal/wins.md`
- [ ] Update `strategy/job-tracker.md` if actively interviewing or applying
- [ ] Log any significant performance feedback in `journal/feedback.md`
- [ ] Review Claim Debt Queue in `identity/claims-and-evidence.md` and check off resolved items

### Monthly (15 minutes)
- [ ] Review and update `identity/skills.yaml` with newly acquired technologies
- [ ] Check `identity/claims-and-evidence.md` — link any newly acquired evidence
- [ ] Review `strategy/study-plan.md` progress and adjust study sprints
- [ ] Warm 2–3 networking connections (see `strategy/networking.md`)
- [ ] Write monthly synthesis in `journal/learning-log.md`

### Quarterly (30 minutes)
- [ ] Audit `identity/experience.yaml` — ensure recent quarters are fully documented
- [ ] Review `strategy/target-roles.md` — re-score candidate roles if market shifted
- [ ] Run resume cascade validation: `python tools/resume/assemble.py --validate`
- [ ] Check for orphaned resume bullets: `python tools/resume/assemble.py --orphans`
- [ ] Check for new credentials in `identity/credentials.yaml`
- [ ] Refresh references in `identity/references.yaml` — ensure 3+ contacts are warm
- [ ] Review Career Contingency Checklists in `identity/claims-and-evidence.md`
- [ ] Execute the 10-Area Audit Checklist below

## 6. 10-Area Systematic Audit Checklist

> Run this comprehensive checklist quarterly or prior to initiating an active job hunt.
> Use prompt #2 ("Full System Audit") from `ops/prompts.md` for AI-assisted audit.

### 1. Contact Consistency
- [ ] `identity/identity.yaml` contact details match `config.yaml`
- [ ] `tools/resume/master.yaml` header matches `identity/identity.yaml`
- [ ] Public platform profiles (LinkedIn, GitHub) match `identity/identity.yaml`
- [ ] All portfolio and social links are live and return HTTP 200

### 2. Experience Freshness
- [ ] Most recent employment work is captured in `identity/experience.yaml`
- [ ] Recent projects have detailed deliverables, metrics, and bullets
- [ ] No accomplishments from the last 3 months are missing
- [ ] All employment dates are accurate and cross-referenced with offer/experience letters

### 3. Skills Accuracy
- [ ] Skills reflect technologies actively used in the last 6 months
- [ ] Proficiency levels match reality (beginner, intermediate, advanced, expert)
- [ ] New tools/frameworks from recent projects have been added
- [ ] Deprecated or legacy skills are downgraded or removed

### 4. Claims Integrity
- [ ] Every resume bullet has a corresponding entry in `identity/claims-and-evidence.md`
- [ ] No ❌ UNVERIFIED claims exist in any active resume variant
- [ ] Metrics are explicitly tagged `[measured]` or `[estimated]`
- [ ] Evidence references point to valid documents in `data-corpus/`

### 5. Resume Cascade Health
- [ ] `python tools/resume/assemble.py --validate` passes with 0 errors
- [ ] All variants build without schema warnings
- [ ] `python tools/resume/assemble.py --orphans` identifies no unused orphan bullets
- [ ] Generated files in `tools/resume/generated/` reflect current master pool

### 6. Verification Coverage
- [ ] > 80% of career claims carry ✅ VERIFIED tags
- [ ] < 10% of career claims carry ❌ UNVERIFIED tags
- [ ] Evidence files exist in `data-corpus/` for all ✅ claims
- [ ] Contradictions log in `claims-and-evidence.md` is fully resolved

### 7. Strategy Alignment
- [ ] Target roles in `strategy/target-roles.md` align with current career aspirations
- [ ] Resume variants exist for all Tier A target roles
- [ ] Study plan in `strategy/study-plan.md` reflects current skill gaps
- [ ] Compensation expectations in `strategy/financial.md` match current market bands

### 8. Privacy & Boundary Check
- [ ] No content from `personal/` leaks into `identity/` or `tools/resume/`
- [ ] No private compensation figures appear in public-facing files
- [ ] Sensitive files in `data-corpus/` are listed in `.gitignore`
- [ ] If repository is hosted publicly, no PII (phone, address, DOB) is committed

### 9. System Completeness
- [ ] Run: `python .pramedha/validate.py --status`
- [ ] Core system fill rate is > 70% for an active job search
- [ ] Professional summary variants in `identity/professional-summary.md` are up to date
- [ ] All sections relevant to target roles have complete information

### 10. Repository & Git Health
- [ ] No uncommitted working tree changes sitting unpushed for > 1 week
- [ ] Commit messages follow descriptive conventional commit standards
- [ ] Build artifacts (`tools/resume/output/*.pdf`) are untracked in `.gitignore`
- [ ] No large binary files (> 10MB) bloat the Git history

### Audit Health Scoring

| Score | Health Status | Recommended Action |
|:-----:|:-------------:|--------------------|
| **10 / 10** | 🟢 Excellent | Maintain regular monthly rituals |
| **7–9 / 10** | 🟡 Good | Resolve failing areas during this week's review |
| **4–6 / 10** | 🟠 Needs Work | Schedule a dedicated 2-hour maintenance session |
| **0–3 / 10** | 🔴 Critical | Fix core identity and claims before submitting applications |

## 7. Anti-Drift Principles

1. **Single Source of Truth:** Each career fact lives in exactly ONE authoritative file (see `ops/authority-map.md`).
2. **Identity Always Wins:** If a resume or LinkedIn profile contradicts `identity/*.yaml`, the resume must be corrected.
3. **Evidence Precedes Claims:** No new bullet enters `experience.yaml` without supporting evidence in `journal/work-log/` or `data-corpus/`.
4. **Verification Precedes Sharing:** Every public-facing claim must be validated through `identity/claims-and-evidence.md`.
