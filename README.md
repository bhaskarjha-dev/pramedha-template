# Pramedha Career Template

> **Your career data — portable, version-controlled, AI-readable, and yours.**

A structured career repository that serves as the **permanent canonical source of truth** about your career.
Fill the YAML + Markdown files with any AI assistant or text editor — no external tools required.
Its schema is designed for Pramedha, a career platform in development (not yet available).

---

## Who it's for

People comfortable with git and an AI coding assistant (Claude Code, Codex, Gemini CLI, Cursor, Copilot)
who want a private, evidence-backed record of their career. Without those tools the YAML and Markdown
files still work in any editor, but the AI fill and the PDF build won't.

## What you need

- A **private** GitHub repository (or plain local git)
- An AI assistant that can read and write files in the repository
- Python 3.12+ for PDFs (3.10+ for everything else), in a virtual environment (`python3 -m venv .venv`, then `python -m pip install -r tools/resume/requirements.txt` inside it)

## See it

[A resume built from the example profile](docs/sample/alex-chen-backend.pdf), generated by `tools/resume/`.

## Limits

- It does not find jobs or apply for you.
- It does not verify claims by itself: ✅ means you (or your assistant) named the evidence: a file or a public URL.
- AI fill quality depends on your assistant; review everything it writes.

## Quick Start

> ⚠️ **DO NOT FORK this repo.** GitHub forks inherit the parent's visibility —
> a fork of a public repo **cannot be made private**. Your salary, DOB, references,
> and career strategy would be exposed. Use one of the methods below instead.

**→ [Read GETTING_STARTED.md](GETTING_STARTED.md) for the full 30-minute walkthrough.**

### Option A: GitHub "Use this template" (Recommended)

1. Click the green **"Use this template"** button at the top of this repo
2. Select **"Create a new repository"**
3. Set visibility to **Private** ✅
4. Clone your new private repo locally

### Option B: Clone + fresh private repo

```bash
# 1. Clone (this does NOT create a fork)
git clone https://github.com/bhaskarjha-dev/pramedha-template my-career
cd my-career

# 2. Disconnect from the template repo
git remote remove origin

# 3. Connect to YOUR private repo
git remote add origin git@github.com:YOUR-USERNAME/my-career.git
git push -u origin main
```

### Option C: Download ZIP

On the repository page, choose **Code → Download ZIP** → extract → `git init` in the folder.

### Then:

```bash
# Dump raw career data into data-corpus/ (inbox/ or archive.zip)
# Let AI fill everything: "Read .pramedha/agent-instructions.md and fill from data-corpus"
# Review what AI filled, add private context, write VISION.md
# One-time setup in the repository folder (Python 3.12+ for PDFs):
python3 -m venv .venv                       # Windows: py -m venv .venv
source .venv/bin/activate                   # macOS / Linux; again in every new terminal
# Windows PowerShell: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force; .venv\Scripts\Activate.ps1
# Windows cmd: .venv\Scripts\activate.bat
python -m pip install -r tools/resume/requirements.txt

# Check fill status:
python .pramedha/validate.py --status

# When applying for a job: sync facts, create a variant and select its bullets, then build
python tools/resume/sync.py
cp tools/resume/variants/_template.yaml tools/resume/variants/my-role.yaml
# Windows: copy tools\resume\variants\_template.yaml tools\resume\variants\my-role.yaml
bash tools/resume/build.sh                                        # macOS / Linux
powershell -ExecutionPolicy Bypass -File tools\resume\build.ps1   # Windows
```

> Inside the virtual environment, `python` is the right interpreter on every OS. On Debian/Ubuntu,
> `python3 -m venv` needs `sudo apt install python3-venv` first. On Python 3.10 or 3.11 everything
> except the PDF build works; PDFs need Python 3.12 or newer.

## Verification System

Every fact in this repo carries a verification tag:

| Tag | Meaning | Use In Resumes? |
|-----|---------|:---------------:|
| `✅ VERIFIED — data-corpus/<file>` | The named evidence file exists (cert, screenshot, doc) or a public URL shows it; `validate.py` checks the path | ✅ Safe |
| `⚠️ ESTIMATED` | Reasonable but unverified | ⚠️ Use carefully |
| `❌ UNVERIFIED` | Aspiration or uncertain claim | ❌ Do not use |

`tools/resume/assemble.py` warns on resume builds that select a ❌ claim (tagged `[unverified]` or `[to-verify]`, or whose role, project or deliverable `verification:` says ❌/UNVERIFIED) and lists every ⚠️ estimated claim it uses.

This maps directly to Pramedha's `ClaimStatus` enum for import.

## Security & Privacy

> 🔴 **Rule #1: Use a PRIVATE repository.**
> This template stores sensitive career data (salary, DOB, references, deal-breakers).
> A private repo is the only safe default.

> 🔴 **Rule #2: NEVER fork a public repo.**
> GitHub forks inherit the parent's visibility. A fork of a public repo **cannot be
> made private**. Use "Use this template" or clone instead (see Quick Start above).

### Sensitivity Map

| File/Folder | Contains | Safe to share outside your private repo? |
|------------|----------|:----------------------------------------:|
| `config.yaml` | Name, email, phone | ⚠️ Only what appears on your resume |
| `identity/identity.yaml` | Date of birth, nationality, visa, pronouns | ❌ **Never public** |
| `identity/` (other files) | Career facts | ⚠️ Only what appears on your resume |
| `identity/references.yaml` | Contact details of references | ❌ **Never public** |
| `personal/` | Life context, salary, deal-breakers, reflections | ❌ **Never public** |
| `data-corpus/` | Raw evidence — certs, offer letters, IDs | ❌ **Never public** |
| `strategy/financial.md` | Current salary, targets | ❌ **Never public** |
| `strategy/networking.md` | Contact details, relationship notes | ❌ **Never public** |
| `personal/form-fill-cheatsheet.md` | DOB, address, phone, references | ❌ **Never public** |
| `journal/feedback.md` | Performance review data | ❌ **Never public** |
| `strategy/job-tracker.md` | Where you are applying | ❌ **Never public** |
| `strategy/offer-comparison.md` | Offer amounts and terms | ❌ **Never public** |
| `ops/session-handoff.md` | AI session notes (decisions, targets) | ❌ **Never public** |
| `tools/resume/output/` | Generated PDFs | ⚠️ Depends on content |

### Public repositories are not supported

Everything in this repository is private by design, including `identity/identity.yaml` (date of birth,
nationality, visa), `strategy/` (applications, offers) and `ops/session-handoff.md`. Keep the repository
private. To publish a resume or a portfolio, copy the generated PDF or chosen text into a separate public
repository. CI fails in any public copy of this template (job `privacy-guard`).

## Validation

Check your template's integrity and fill status:

```bash
python .pramedha/validate.py                  # Core career profile validation (0 resume dependency)
python .pramedha/validate.py --status         # Fill percentage only
python .pramedha/validate.py --with-resume    # Also check variant references (claim checks: tools/resume/assemble.py --validate)
python .pramedha/validate.py --strict         # Fail on warnings too
```

## Staying Updated

Your copy has no link to the template. To receive fixes, add the template once as a remote, then run
the update script. It replaces only the files the template owns (the `template_owned` list in
`.pramedha/manifest.yaml`) and never touches your data, `config.yaml`, `VISION.md`, `AGENTS.md` or
`.gitignore`; when the template changed `AGENTS.md` or `.gitignore`, it prints the command to compare them.

```bash
# Once:
git remote add upstream https://github.com/bhaskarjha-dev/pramedha-template.git

# Once, if your copy has no tools/update_template.py yet (copies made before this update):
git fetch upstream
git checkout upstream/main -- tools/update_template.py tools/resume/requirements.txt
git commit -m "Add template update script"

# Each time (inside the virtual environment):
git fetch upstream
python tools/update_template.py --dry-run    # what would change
python tools/update_template.py              # replace template-owned files
git diff --staged                            # review, then commit
git commit -m "Update template files"
```

Don't merge the template's branch into your repository: the histories are unrelated, and a merge either
keeps your old template files or replaces your filled data with empty templates.
